# 确认门清单

在写完整场景、出全片之前，逐项确认。每一轮只推进一项；用户改了哪项，就回到哪项重确认。

## 1. 需求

- [ ] 画幅与像素：16:9 / 9:16 / 1:1
- [ ] 时长
- [ ] 交付：先出帧 / 静音 mp4 / 旁白 + 字幕（HF）
- [ ] 风格（或“你决定”）
- [ ] 受众（数学/科学题材）
- [ ] 旁白语言与声音（仅旁白交付）

## 2. 脚本 / 文案

| # | 旁白（逐句） | 上屏文字 | 公式 | 备注 |
|---|---|---|---|---|
| 1 |  |  |  |  |

- 公式先过 `formula_check`；
- 旁白按“一句一个意思”拆，标出预计秒数；
- 没有旁白就只填上屏文字与公式。

## 3. 分镜

| # | 起止秒 | 画面 | 运动 | 字幕 / 旁白 | 验收点 |
|---|---|---|---|---|---|
| 1 | 0.0–2.0 |  |  |  |  |

- 镜头数按内容定，不为了凑时长加镜头；
- 每个镜头写清“观众看到什么变化”；
- 结论镜头要留够阅读时间（≥1.2 s）。

## 4. 视觉

- [ ] `DESIGN.md`：颜色、字体、禁用项、参考
- [ ] 3 张风格帧：开场 / 转折 / 结论（真实代码出帧，不渲染视频）
- [ ] 风格帧通过 `motion_frames` 的 layout 检查

## 5. 交付清单

- [ ] 尺寸 / fps / 时长
- [ ] 文件：mp4 / `.srt` / 场景源码 / DESIGN.md / 分镜表
- [ ] 音频：无 / 旁白 / 音乐；响度目标
- [ ] 字幕：烧录 / 外挂 / 两者

## 6. 开工指令

只有用户**明确**说出下面这类话，才进入执行：

- “可以开始”
- “开始做”
- “按这个执行”
- “开工”

以下**不算**整体开工：

- 对某个选项说“好 / 可以 / 行”；
- 确认了脚本或分镜；
- 说“看着办”但没有明确授权执行。

不确定时问一句：“脚本、分镜、风格帧都确认了，现在开始执行吗？”
